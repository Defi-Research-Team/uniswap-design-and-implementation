# 定点数

上一章我们建立了 AMM 的数学理论框架。在深入 Uniswap 的合约源码之前，还需要先解决一个工程层面的基础问题：**Solidity 没有浮点数**。

这意味着我们无法在合约中直接使用小数来表示价格、汇率等数值。比如 ETH 的价格可能是 2000.5 USDC，但 Solidity 只能处理整数。Uniswap 需要在纯整数环境下进行精确的价格计算——这就是定点数（Fixed-Point Number）运算要解决的问题。

本章我们聚焦于定点数的理论基础：为什么需要定点数、Q 数格式的原理、运算规则，以及 Uniswap 采用的具体格式如何体现这些原理。理解了这些基础概念后，在后续章节分析 Uniswap 各版本的合约实现时，读者将能够轻松理解其中的定点数运算逻辑。

## 问题

Solidity 目前不支持浮点数类型（`float` / `double`）。链上的所有算术运算都是整数运算，这意味着：

- 无法直接表示 `2000.5` 这样的数值
- 整数除法会截断小数部分：`5 / 2 = 2`（而非 2.5）
- 价格、汇率、比例等涉及小数的计算都需要特殊处理

面对这个约束，有三种常见方案：

| 方案       | 思路                       | 例子                                    |
| ---------- | -------------------------- | --------------------------------------- |
| 放大单位   | 用更大的单位表示，避免小数 | Wei（1 ETH = 10¹⁸ Wei）                 |
| 有理数表示 | 分子/分母形式              | 储备比值直接用 reserve0 / reserve1 表示 |
| 定点数     | 用固定位数的整数模拟小数   | 价格、平方根价格等精确数值              |

**放大单位**可以解决 ETH/USDC 这种数量级的表示问题（用 Wei 代替 ETH），但无法解决价格比值的精确计算——比如 1 USDC 兑多少 ETH，这个比值可能非常小（如 0.0005），单纯放大单位难以精确表示。

**有理数表示**在某些场景下可用，但当需要在合约中存储和运算价格（而非即时计算比值）时，单一的数值形式更为方便。

**定点数**是 Uniswap 采用的核心方案。其思路很朴素：用一个整数，约定其中某些二进制位表示整数部分，其余位表示小数部分。

## Q 数格式

定点数的标准表示方法是 **Q 格式**，记作 Qm.n，其中：

- **m** 是整数部分的位数（不包括符号位）
- **n** 是小数部分的位数

对于无符号定点数，常用 UQm.n 表示。

一个 Qm.n 格式的定点数，本质上是一个整数，其存储值等于实际值乘以 $2^n$（即小数部分的位数决定了缩放因子）。

```
┌─────────────────────────────────┬─────────────────────────────────┐
│         整数部分 (m 位)          │         小数部分 (n 位)          │
└─────────────────────────────────┴─────────────────────────────────┘
```

例如，要表示实际值 `1.5`，在 Q64.96 格式中：

- 缩放因子为 $2^{96}$
- 存储值 = $\lfloor 1.5 \times 2^{96} \rfloor$
- 二进制表示：整数部分为 `1`，小数部分为 `.1`（即 0.5）

### 编码与解码

**编码**（将实际值转换为定点数）：

$$\text{encoded} = \lfloor \text{value} \times 2^n \rfloor$$

在 Solidity 中，这等价于将整数值左移 $n$ 位：

```solidity
// 编码：将整数 y 转换为 Qn 格式定点数
uint256 encoded = uint256(y) << n;  // 等价于 y * 2^n
```

**解码**（将定点数还原为实际值）：

$$\text{value} = \frac{\text{encoded}}{2^n}$$

在 Solidity 中，这等价于将定点数右移 $n$ 位（如果只需要整数部分）：

```solidity
// 解码：从 Qn 格式定点数中提取整数部分
uint256 integerValue = encoded >> n;  // 等价于 encoded / 2^n
```

注意，右移会截断小数部分。如果需要更高精度，可以保留定点数形式继续运算，只在最终需要展示时解码。

### 精度与范围

Q 格式面临**范围与精度的权衡**：

- **整数部分位数越多** → 能表示的数值范围越大，但小数精度越低
- **小数部分位数越多** → 小数精度越高，但数值范围越小

在总位数固定的情况下（如 Solidity 的 `uint256`、`uint160`、`uint128` 等），需要在两者之间做出权衡。

**精度**由小数部分的位数决定。Qn 格式的最小可表示单位（精度）为 $2^{-n}$，即能区分的最小差异为 $1/2^n$。

**范围**由整数部分的位数决定。Qm.n 格式的无符号表示范围为 $[0, 2^m - 2^{-n}]$，最大可表示的整数值为 $2^m - 1$。

以 Uniswap 采用的几种格式为例来说明：

| 格式      | 总位数 | 缩放因子  | 整数范围         | 小数精度                       |
| --------- | ------ | --------- | ---------------- | ------------------------------ |
| UQ112.112 | 224    | $2^{112}$ | $[0, 2^{112}-1]$ | $\approx 1.93 \times 10^{-34}$ |
| UQ64.96   | 160    | $2^{96}$  | $[0, 2^{64}-1]$  | $\approx 1.26 \times 10^{-29}$ |
| UQ128.128 | 256    | $2^{128}$ | $[0, 2^{128}-1]$ | $\approx 2.94 \times 10^{-39}$ |

可以看到，即使只有 96 位的小数部分，精度也达到了 $10^{-29}$ 级别——对于金融计算而言绰绰有余。

我们用一个例子来直观感受精度

以 UQ64.96 格式为例，来直观感受 96 位小数部分的精度。

假设 ETH 的价格为 2000 USDC，对应的 $\sqrt{P} = \sqrt{2000} \approx 44.7213595499958$。

在 UQ64.96 格式中：

$$\sqrt{P}_{\text{encoded}} = \lfloor 44.7213595499958 \times 2^{96} \rfloor = 3544233733328802452386847$$

解码还原：

$$\sqrt{P}_{\text{decoded}} = \frac{3544233733328802452386847}{2^{96}} \approx 44.721359549995796$$

与原始值相比，误差在 $10^{-15}$ 量级——对于链上价格计算完全足够。

实际价格 $P$ 通过 $\sqrt{P}$ 的平方还原：

$$P = \left(\frac{\sqrt{P}_{\text{encoded}}}{2^{96}}\right)^2 = \frac{\sqrt{P}_{\text{encoded}}^2}{2^{192}}$$

这一还原过程涉及定点数的乘法运算，下面我们来详细分析。

## 运算规则

定点数运算的核心挑战在于：**所有运算仍然在整数域内执行，但必须保持正确的缩放关系**。

### 加法

两个相同格式的定点数相加或相减，结果仍然是同一格式的定点数，无需额外处理：

```solidity
// 加法：Qn + Qn = Qn
uint256 sum = a + b;

// 减法：Qn - Qn = Qn
uint256 diff = a - b;
```

这是因为缩放因子 $2^n$ 在加减法中自然保持一致：$(a \times 2^n) \pm (b \times 2^n) = (a \pm b) \times 2^n$。

注意溢出检查。在 Solidity 0.8+ 中，`uint256` 的算术运算默认检查溢出。

### 乘法

两个 Qn 格式的定点数相乘，结果的缩放因子变为 $2^{2n}$，需要除以 $2^n$（即右移 $n$ 位）恢复到原始格式：

$$a_{\text{Qn}} \times b_{\text{Qn}} = (a \times 2^n) \times (b \times 2^n) = a \times b \times 2^{2n}$$

需要除以 $2^n$ 恢复为 Qn 格式：$a \times b \times 2^{2n} / 2^n = a \times b \times 2^n$。

```solidity
// 乘法：Qn × Qn → 需要右移 n 位恢复格式
uint256 product = (a * b) >> n;  // 等价于 a * b / 2^n
```

**问题**：中间乘积 $a \times b$ 可能溢出 `uint256` 的范围。

**常见但不完美的做法**：先除后乘——`a * (b >> n)` 或 `(a >> n) * b`。但这会先做右移截断，丢失精度。

**正确的做法**：使用宽位乘法（如 512 位中间精度），保证乘积不溢出的同时不丢失精度。Uniswap 的 `FullMath` 库就实现了这种全精度乘法，将在后续 V3 章中详细分析其实现。

定点数乘以一个普通整数，结果仍然是同一格式的定点数，无需调整缩放：

$$a_{\text{Qn}} \times b_{\text{int}} = (a \times 2^n) \times b = (a \times b) \times 2^n$$

```solidity
// 定点数 × 整数 → 直接乘
uint256 result = fixedPointA * integerB;
```

这是最简单的乘法形式。注意结果可能溢出。

### 除法

两个 Qn 格式的定点数相除，结果的缩放因子变为 $2^0 = 1$（即变成普通整数），需要乘以 $2^n$（即左移 $n$ 位）恢复格式：

$$\frac{a_{\text{Qn}}}{b_{\text{Qn}}} = \frac{a \times 2^n}{b \times 2^n} = \frac{a}{b}$$

需要乘以 $2^n$ 恢复为 Qn 格式。

```solidity
// 除法：Qn ÷ Qn → 需要左移 n 位恢复格式
uint256 quotient = (a << n) / b;  // 先放大被除数再除
```

**关键**：必须先左移被除数（放大），再做整数除法。如果先做除法再移位，小数部分会被截断丢失。

定点数除以一个普通整数，结果仍然是同一格式的定点数，无需调整缩放：

$$\frac{a_{\text{Qn}}}{b_{\text{int}}} = \frac{a \times 2^n}{b} = \left(\frac{a}{b}\right) \times 2^n$$

```solidity
// 定点数 ÷ 整数 → 直接除
uint256 result = fixedPointA / integerB;
```

注意整数除法会截断，但由于被除数已经是放大的定点数，截断的精度损失很小。

### 运算规则速查

| 运算      | 操作                  | 缩放因子变化       |
| --------- | --------------------- | ------------------ |
| Qn ± Qn   | 直接加减              | 不变（仍为 $2^n$） |
| Qn × Qn   | 乘积右移 $n$ 位       | $2^{2n} → 2^n$     |
| Qn × 整数 | 直接乘                | 不变（仍为 $2^n$） |
| Qn ÷ Qn   | 被除数左移 $n$ 位再除 | $2^0 → 2^n$        |
| Qn ÷ 整数 | 直接除                | 不变（仍为 $2^n$） |

### 完整示例

假设我们用 UQ64.96 格式（即 $n = 96$）进行以下计算：

已知 $\sqrt{P} \approx 44.72$（对应价格 $P \approx 2000$），流动性 $L = 1000000$。

**编码**：

$$\sqrt{P}_{\text{Q96}} = \lfloor 44.72 \times 2^{96} \rfloor = 3544233733328802452386847$$

**计算 $\sqrt{P} \times L$**（定点数 × 整数）：

这是定点数乘以整数，直接相乘即可：

$$\text{result} = \sqrt{P}_{\text{Q96}} \times L = 3544233733328802452386847 \times 1000000$$

结果仍然是 Q96 格式。

**计算 $\sqrt{P}^2$**（定点数 × 定点数）：

两个 Q96 数相乘，需要右移 96 位：

$$\sqrt{P}^2_{\text{Q96}} = (\sqrt{P}_{\text{Q96}} \times \sqrt{P}_{\text{Q96}}) >> 96$$

这就还原出了 Q96 格式的价格 $P$。

**溢出问题**：$\sqrt{P}_{\text{Q96}} \times \sqrt{P}_{\text{Q96}}$ 是两个约 $3.5 \times 10^{24}$ 的数相乘，结果约为 $1.26 \times 10^{49}$，远超 `uint256` 的最大值（约 $1.16 \times 10^{77}$），但中间乘积 $\sqrt{P}_{\text{Q96}} \times \sqrt{P}_{\text{Q96}}$ 约为 $1.26 \times 10^{49}$，在 `uint256` 范围内。然而，当 $\sqrt{P}$ 更大时，中间乘积可能溢出——这正是需要宽位乘法的原因。

## Solidity 实现

定点数编码和解码是所有运算的基础。以下是一个通用的实现模式：

```solidity
library FixedPoint {
    uint256 internal constant Q96 = 2 ** 96;  // 缩放因子

    // 编码：将整数转换为 Q96 定点数
    function encode(uint256 value) internal pure returns (uint256) {
        return value * Q96;  // 等价于 value << 96
    }

    // 解码：从 Q96 定点数中提取整数部分
    function decode(uint256 fixedValue) internal pure returns (uint256) {
        return fixedValue / Q96;  // 等价于 fixedValue >> 96
    }
}
```

编码时使用乘法（`value * Q96`）或等价的左移（`value << 96`）；解码时使用除法（`fixedValue / Q96`）或等价的右移（`fixedValue >> 96`）。

定点数乘法是使用最频繁也最容易出问题的运算。根据场景不同，有不同的实现策略。

**模式一：定点数 × 整数（简单）**

```solidity
function mulUInt(uint256 fixedA, uint256 integerB) internal pure returns (uint256) {
    return fixedA * integerB;
    // Qn × int → Qn，无需调整缩放
}
```

需要注意溢出：如果 `fixedA` 和 `integerB` 都较大，乘积可能超出 `uint256` 范围。

**模式二：定点数 ÷ 整数（简单）**

```solidity
function divUInt(uint256 fixedA, uint256 integerB) internal pure returns (uint256) {
    require(integerB > 0, "Division by zero");
    return fixedA / integerB;
    // Qn ÷ int → Qn，无需调整缩放
}
```

**模式三：定点数 × 定点数（需要精度保护）**

这是最复杂的场景。有两种实现策略：

**策略 A：先除后乘（节省 Gas，丢失精度）**

```solidity
function mulNaive(uint256 fixedA, uint256 fixedB, uint8 n) internal pure returns (uint256) {
    return (fixedA >> n) * fixedB;  // 先右移 n 位缩小，再乘
}
```

右移截断了 `fixedA` 的低 $n$ 位信息，引入误差。

**策略 B：全精度乘法（精确，Gas 更高）**

将 $a \times b$ 的乘积用两个 256 位变量（共 512 位）存储，然后对 512 位数执行除法，最终截取低 256 位作为结果。这就是 Uniswap 的 `FullMath.mulDiv` 采用的核心思路，将在 V3 章中详细分析其实现。

### 溢出保护

在 Solidity 中进行定点数运算时，溢出是必须考虑的问题。特别是：

- **编码溢出**：`value * Q96` 可能超出目标类型的范围。例如，将一个大整数编码为 Q96 格式存入 `uint160`，需要确保 `value * 2^96 < 2^{160}`
- **运算溢出**：乘法中间结果可能超出 `uint256` 范围
- **截断溢出**：类型转换时（如 `uint256` → `uint160`），如果值超出目标类型范围，必须回退而非静默截断

Uniswap 使用 `SafeCast` 库来处理这些问题。其核心模式是：先执行转换，再检查值是否不变：

```solidity
function toUint160(uint256 y) internal pure returns (uint160 z) {
    require((z = uint160(y)) == y);  // 如果截断发生，z ≠ y，回退
}
```

这种"先转换、后校验"的模式既简洁又安全。

## 总结

- **问题**：Solidity 不支持浮点数类型，所有算术运算都是整数运算。价格、汇率、比例等涉及小数的计算需要通过定点数来解决
- **Q 格式**：用固定位数的整数模拟小数。Qm.n 格式中，m 位表示整数部分，n 位表示小数部分，存储值 = 实际值 × $2^n$
- **精度与范围**：Q 格式面临精度与范围的权衡。Uniswap 采用的 96 位小数精度（$10^{-29}$ 级别）对金融计算绰绰有余
- **运算规则**：加减法直接运算；乘法需要调整缩放（右移）；除法需要先放大再除（左移）。定点数 × 整数和定点数 ÷ 整数是最简单的运算形式
- **溢出与精度**：乘法中间值可能溢出 `uint256`，需要宽位乘法技术保证精度；类型转换需要安全检查防止静默截断
- **设计考量**：选择 Q 格式时需要综合考虑值域需求、精度需求、存储效率、与其他数据的配合以及中间运算的溢出风险
