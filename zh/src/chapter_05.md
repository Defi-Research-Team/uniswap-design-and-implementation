# 费用机制

第 1 章在理想条件下推导了恒定乘积做市商的全部公式，但现实中价格变动会带来无常损失，使流动性提供者承担亏损，因此必须引入交易手续费作为激励机制以补偿其风险。在此基础上，协议方还可选择开启协议费，从手续费中分取一部分以奖励协议开发者。本章聚焦这两类费用的设计原理与数学推导，具体的合约实现将留至第 7 章。

## 交易手续费

Uniswap V2 规定每笔交易收取 $0.3\%$ 的手续费。但要注意，这笔费用**不是**从交易者换得的资产里直接扣除 $0.3\%$。设交易者想用 $\Delta x$ 个代币 X 换取代币 Y，手续费率记为 $\gamma$（现实中 $\gamma = 0.003$），则手续费的收取过程是：

1. 先从交易者投入的 $\Delta x$ 中扣除 $\gamma\Delta x$，只有剩下的 $(1-\gamma)\Delta x$ 参与恒定乘积的计算；
2. 用 $(1-\gamma)\Delta x$ 按乘积不变规则，算出交易者实际能换得的 $\Delta y$；
3. 若不扣费，按第 1 章的交易公式交易者本可换得更多的 $\Delta y'$，则 $\Delta y' - \Delta y$ 就是这笔交易实际支付的手续费。

关键在于：扣费只发生在“计算可换得数量”这一步。交易完成后，交易者实际转入池子的代币 X 仍是完整的 $\Delta x$。少转出的那部分代币 Y，才是手续费的真正来源。

设交易前池子的乘积为 $k$，上述第 1、2 步写成等式就是：

$$(x + (1-\gamma)\Delta x)(y - \Delta y) = k \tag{1}$$

解出 $\Delta y$：

$$\Delta y = \frac{(1-\gamma)\Delta x}{x + (1-\gamma)\Delta x}\,y \tag{2}$$

而不扣费时，按第 1 章的交易公式，交易者本应换得：

$$\Delta y' = \frac{\Delta x}{x + \Delta x}\,y \tag{3}$$

两式相除并化简：

$$\frac{\Delta y}{\Delta y'} = 1 - \frac{\gamma x}{x + (1-\gamma)\Delta x} = 1 - \frac{\gamma}{1 + (1-\gamma)\dfrac{\Delta x}{x}} \tag{4}$$

由式 (4)，只要 $\gamma \ne 0$，比值就恒小于 1，少掉的那一部分正是池子收取的手续费。举例：取 $x = 1000$、$\Delta x = 1$，代入式 (4) 得 $\Delta y / \Delta y' \approx 0.997003$，即交易者实际换得的数量约为无手续费时的 $0.997$ 倍，差额约 $0.003$，与名义费率 $\gamma$ 几乎一致。从式 (4) 也能看出：$\Delta x / x$ 越小（单笔交易相对池子越小），比值就越贴近 $1 - \gamma$。这与直觉相符：交易量相对于池子越小，价格冲击越小，实际费率就越接近名义费率。

现在来看手续费去哪了。交易完成后，池子储备量的乘积不再等于 $k$，而是变大了一点：

$$k' = (x + \Delta x)\!\left(y - \frac{(1-\gamma)\Delta x}{x + (1-\gamma)\Delta x}\,y\right) = k\cdot\frac{x + \Delta x}{x + (1-\gamma)\Delta x} > k \tag{5}$$

道理很直白：若没有手续费，交易后的乘积仍是 $k$；但因为有手续费，本该转出的 $\Delta y$ 被少转出了一截、留在了池子里，乘积自然变大。这一截被截留的部分，就是手续费的来源。换言之，**每一笔交易都让池子的 $k$ 略微增长，累积的增长就是全体 LP 共同赚取的手续费**。

![手续费使 k 增长](images/ch05/fee_growth.png)

_图 1　带手续费的交易使池子从曲线 $xy = k$ 跳到更高的曲线 $xy = k' > k$。无手续费时，交易沿原曲线从 A 移动到 B；扣费后交易者少得一部分 Y，储备点落在更高的 B'，竖直方向多出的那一段（绿色）即留存的手续费。为便于观察，图中费率已放大；V2 实际为 $0.3\%$。_

几何上看（图 1），无手续费的交易让池子状态沿曲线 $xy = k$ 从 A 滑到 B；而带手续费的交易，由于交易者换得的 $\Delta y$ 偏少，储备点会落在原曲线**上方**的 B'，它对应一条更高的曲线 $xy = k'$。A 到 B' 之间的这记“上跳”，正是 $k$ 的增长。

手续费以增大储备量的形式留在池中，而 LP 取回资产时是按其持有的流动性份额等比例提取的（第 1 章的移除流动性公式）。份额没变、池子却变大了，LP 自然就分到了这份增长，这就是 LP 赚取手续费的途径，无需任何额外的记账。

这个结论可以用流动性严格表达。回顾第 1 章，添加流动性时贡献 $\Delta L$ 所需的两种资产满足 $\Delta L = L\,\Delta x / x = L\,\Delta y / y$（其中 $L$ 是池子总流动性），两边取几何平均可得

$$\sqrt{\Delta x_1\,\Delta y_1} = \frac{\Delta L}{L_1}\sqrt{k_1} \tag{6}$$

其中 $L_1$、$k_1$ 是添加时的总流动性与乘积。同理，移除流动性时取回的资产满足

$$\sqrt{\Delta x_2\,\Delta y_2} = \frac{\Delta L}{L_2}\sqrt{k_2} \tag{7}$$

其中 $L_2$、$k_2$ 是移除时的总流动性与乘积。两式相减：

$$\sqrt{\Delta x_2\,\Delta y_2} - \sqrt{\Delta x_1\,\Delta y_1} = \frac{\Delta L}{L_2}\sqrt{k_2} - \frac{\Delta L}{L_1}\sqrt{k_1} \tag{8}$$

式 (8) 的含义是：在“两种资产数量的几何平均”这一尺度下，LP 持有期间净赚（或净亏）的量，等于池子乘积的相对增量按其份额摊到的部分。注意从 $k_1$ 到 $k_2$、$L_1$ 到 $L_2$ 的过程中，可能掺杂了各种交易以及流动性的增减，因此式 (8) 的值并不保证为正，这从另一个角度体现了第 1 章的无常损失：价格变动带来的损失可能吃掉手续费收益。

这里之所以用几何平均 $\sqrt{\Delta x\,\Delta y}$ 而非单种资产来度量，是因为 LP 的收益同时体现在 X 和 Y 两种资产上，几何平均恰好抵消掉价格变动的影响，只留下“池子整体变大”的那一部分。

## 协议费

手续费默认全部归 LP。在此基础上，协议方可选择开启协议费：从已收取的手续费中再分出一定比例给协议。把协议方看作一个“特殊的 LP”，问题就变成：它该分到多少、又如何兑现？

V2 规定协议费最多占全部手续费的 $1/6$。由于手续费率是 $0.3\%$，其 $1/6$ 即交易量的 $0.05\%$。记协议费占手续费的比例为 $\phi = 1/6$。

协议费的结算并不在每笔交易时进行，而是在有人添加或移除流动性时一次性算清。这种 _懒惰评估（lazy evaluation）_ 的设计原理与代价将在第 7 章结合 `_mintFee` 的实现展开。两次结算之间，若只有交易发生、没有流动性的增减，则总流动性 $L$ 保持不变，即式 (8) 中 $L_2 = L_1$，化为

$$\frac{\Delta L}{L_1}\bigl(\sqrt{k_2} - \sqrt{k_1}\bigr) \tag{9}$$

也就是说，每个持有 $\Delta L$ 的 LP 在这段窗口内分到的手续费为 $\dfrac{\Delta L}{L_1}\bigl(\sqrt{k_2} - \sqrt{k_1}\bigr)$。对所有 LP 求和（$\sum \Delta L = L_1$），整池在这段时间累积的手续费，在流动性尺度下恰等于

$$\sqrt{k_2} - \sqrt{k_1} \tag{10}$$

这正是协议费要用 $\sqrt{k}$（而非 $k$）来度量增长的原因。第 1 章已定义流动性 $L = \sqrt{xy} = \sqrt{k}$，LP Token 也正是按流动性铸造的，所以 $\sqrt{k}$ 与 LP 份额同处一个尺度。按 $\sqrt{k}$ 的增长来分配，才能保证协议分走的份额与既有 LP 被稀释的份额严格成比例。若改用 $k$（它是 $L$ 的平方），增长会被二次放大，协议就会多拿。

协议的兑现方式是给协议地址新铸 $\Delta L$ 个 LP Token，靠稀释其他 LP 的份额来分得手续费。设铸造前总供应量为 $S$，铸后协议持有的份额为 $\dfrac{\Delta L}{S + \Delta L}$；而整池的价值在流动性尺度下正比于 $\sqrt{k_2}$，故协议分得的价值为 $\dfrac{\Delta L}{S + \Delta L}\sqrt{k_2}$。令它等于按比例应得的 $\phi\bigl(\sqrt{k_2} - \sqrt{k_1}\bigr)$：

$$\frac{\Delta L}{S + \Delta L}\sqrt{k_2} = \phi\bigl(\sqrt{k_2} - \sqrt{k_1}\bigr) \tag{11}$$

解这个关于 $\Delta L$ 的方程：

$$\Delta L = \frac{S\bigl(\sqrt{k_2} - \sqrt{k_1}\bigr)}{\bigl(\tfrac{1}{\phi} - 1\bigr)\sqrt{k_2} + \sqrt{k_1}} \tag{12}$$

代入 $\phi = 1/6$（于是 $1/\phi - 1 = 5$）：

$$\Delta L = \frac{S\bigl(\sqrt{k_2} - \sqrt{k_1}\bigr)}{5\sqrt{k_2} + \sqrt{k_1}} \tag{13}$$

式 (13) 即 Uniswap V2 白皮书 §5.1 的协议费铸币公式（公式 (24)–(25)）。把它对应到合约语言：$S$ 是结算时的 LP Token 总供应量，$k_2$ 是当前的 `reserve0 * reserve1`，$k_1$ 是上次结算时记录的乘积（合约中记作 `kLast`）。合约里的写法 `liquidity = totalSupply * (rootK - rootKLast) / (5 * rootK + rootKLast)` 与式 (13) 逐项一致，分母里的系数 $5$ 正是 $1/6$ 这一副费率留下的痕迹。完整的 `_mintFee` 实现见第 7 章。

## 总结

Uniswap V2 对每笔交易收取 $0.3\%$ 的手续费，这笔费用并非从换得的资产中扣除，而是先从投入量中扣去 $\gamma\Delta x$ 再按乘积不变算出输出，少转出的代币即为手续费。被截留的部分留在池中，使乘积从 $k$ 增长到 $k' > k$，累积的增长就是 LP 凭份额自动分得的手续费收益，无需额外记账。在手续费之上，协议方可选择开启协议费，从已收取的手续费中最多取走 $1/6$（即交易量的 $0.05\%$），并以 LP Token 形式铸造给协议地址。协议费的结算采用懒惰评估、开关由治理控制，具体的实现机制详见第 7 章。
